WEALTH PACK - Signal Type Vocabulary

CRITICAL: Extract structured FACTS into payload fields. DO NOT invent titles.
Titles are generated deterministically from templates after extraction.

=== CANONICAL SIGNAL TYPES ===

1. concentration_breach
   - Description: Single position or sector exceeds concentration limit
   - REQUIRED fields: subject, metric, threshold, current_value
   - Optional: client_id, portfolio_id, evidence_text
   - Example source: "AAPL position at 18% of portfolio exceeds 10% single-stock limit"
   - Extract: { subject: "AAPL", metric: "% of portfolio", threshold: "10%", current_value: "18%" }

2. lookthrough_missing
   - Description: Required lookthrough data unavailable for compliance check
   - REQUIRED fields: subject, rule, missing_data
   - Optional: impact, client_id, portfolio_id
   - Example source: "Unable to verify Rule 144A compliance - missing XYZ Fund holdings"
   - Extract: { subject: "XYZ Fund", rule: "Rule 144A compliance", missing_data: "underlying holdings" }

3. fee_discrepancy
   - Description: Charged fee differs from expected fee schedule
   - REQUIRED fields: charged, expected
   - Optional: fee_type, period, amount_impact, missing_doc, client_id, portfolio_id
   - Example source: "Q4 management fee of 0.35% charged vs 0.25% in fee schedule"
   - Extract: { charged: "0.35%", expected: "0.25%", fee_type: "management", period: "Q4" }

4. settlement_pending_cash
   - Description: Pending settlement proceeds included in cash calculations
   - REQUIRED fields: amount, impact
   - Optional: settlement_date, value_date, affects_liquidity, client_id, portfolio_id
   - Example source: "$250K pending settlement included in available cash for margin"
   - Extract: { amount: "$250K", impact: "available cash for margin calculation" }

5. suitability_drift
   - Description: Portfolio risk profile drifted from client's stated tolerance
   - REQUIRED fields: client, current_risk, target_risk
   - Optional: drift_direction, contributing_factors, client_id, portfolio_id
   - Example source: "Johnson portfolio now Aggressive vs Moderate target"
   - Extract: { client: "Johnson", current_risk: "Aggressive", target_risk: "Moderate", drift_direction: "more_aggressive" }

6. mandate_breach
   - Description: Investment violates client mandate or IPS constraints
   - REQUIRED fields: constraint, current, limit
   - Optional: asset_class, ips_reference, client_id, portfolio_id
   - Example source: "Real estate allocation at 25% exceeds 15% IPS maximum"
   - Extract: { constraint: "Real estate allocation", current: "25%", limit: "15% maximum" }

7. rebalancing_required
   - Description: Portfolio allocation drifted beyond rebalancing threshold
   - REQUIRED fields: portfolio, max_drift
   - Optional: trigger_type, days_since_rebalance, asset_classes_affected, client_id, portfolio_id
   - Example source: "Smith IRA - 12% max drift, 180 days since last rebalance"
   - Extract: { portfolio: "Smith IRA", max_drift: "12%", days_since_rebalance: 180 }

8. tax_harvest_opportunity
   - Description: Tax-loss harvesting opportunity identified
   - REQUIRED fields: security, unrealized_loss
   - Optional: cost_basis, current_value, holding_period, wash_sale_risk, estimated_tax_savings, client_id, portfolio_id
   - Example source: "TSLA shows $45K unrealized loss, potential $13.5K tax savings"
   - Extract: { security: "TSLA", unrealized_loss: "$45K", estimated_tax_savings: "$13.5K" }

9. withdrawal_request
   - Description: Client withdrawal request requiring review
   - REQUIRED fields: client, amount, percent_of_portfolio
   - Optional: liquidation_required, reason, requested_date, client_id, portfolio_id
   - Example source: "Williams requesting $250K withdrawal (15% of portfolio) for home purchase"
   - Extract: { client: "Williams", amount: "$250K", percent_of_portfolio: "15%", reason: "home purchase" }

10. risk_tolerance_change
    - Description: Client's risk tolerance has changed
    - REQUIRED fields: client, previous, new_tolerance
    - Optional: reason, client_id
    - Example source: "Chen moved from Aggressive to Moderate following retirement announcement"
    - Extract: { client: "Chen", previous: "Aggressive", new_tolerance: "Moderate", reason: "retirement" }

11. objective_change
    - Description: Client's investment objective has changed
    - REQUIRED fields: client, previous, new_objective
    - Optional: reason, client_id
    - Example source: "Davis shifted from Growth to Income Generation, cites retirement planning"
    - Extract: { client: "Davis", previous: "Growth", new_objective: "Income Generation", reason: "retirement planning" }

12. compliance_flag
    - Description: Potential compliance issue requiring review
    - REQUIRED fields: issue_type, subject, regulation
    - Optional: details, evidence_text, client_id
    - Example source: "Pattern day trading detected in Martinez account, FINRA Rule 4210"
    - Extract: { issue_type: "Pattern day trading", subject: "Martinez account", regulation: "FINRA Rule 4210" }

=== EXTRACTION RULES ===

1. ONLY use signal types from the list above
2. ALWAYS extract ALL required fields - use null if not explicitly stated
3. Preserve exact values with units as stated in document
4. Include source_spans pointing to exact quoted text
5. Be honest with confidence scores - lower is better than guessing
6. Client names should be extracted as stated, not invented
